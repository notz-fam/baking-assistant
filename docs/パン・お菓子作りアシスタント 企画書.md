# パン・お菓子作りアシスタント 企画書

Nov 5, 2026 · @notz

## アプリ概要

Webのレシピを取り込んで、生地を触っている手のままでも最後まで作れるようにする、パン・お菓子作り用のレシピビューアです。

- **一言で言うと**：「上から読むと気づけない段取り」を先回りして教え、手を触れずに1ステップずつ進められるレシピ
- **対象ユーザー**：YouTubeやcottaなどのレシピを見ながら、パンやお菓子を家で作る人
- **使う場面**：スマホを作業台に平らに置き、こねる・混ぜる・量るをしながら見る
- **アプリ名**：未定（プレゼンまでに決める）

## 背景と課題

パン・お菓子作りは、「手が粉と生地まみれ」「工程が長く待ち時間が多い」「環境で結果が変わる」という点で、普通の料理とは困りごとの種類が違います。

| 分類 | 困りごと | 1時間版での扱い |
| --- | --- | --- |
| 作業中の操作 | 生地を触った手でスマホのレシピを見づらい・操作しづらい | 対応（調理モード） |
| 作業中の操作 | YouTubeレシピは動画の停止と再生を何度も繰り返す | 公開版で |
| 計量と計算 | 分量を変えるとき（粉200g→300g）の換算が面倒 | 対応（分量換算） |
| 計量と計算 | 計量そのものが面倒 | 公開版で |
| 段取り | 「予熱しておいたオーブン」がレシピ後半で初めて出てくる | 対応（始める前チェックリスト） |
| 段取り | バターやクリームチーズを常温に戻しておく必要がある | 対応（始める前チェックリスト） |
| 環境の違い | オーブンによって焼き具合が違い、温度や時間の調整が要る | 公開版で |

実例：cottaの[スフレチーズケーキ](https://www.cotta.jp/recipe/recipe.php?recipeid=00013468)では、「150℃に予熱したオーブン」と「湯をはったバット」がどちらも手順の後半で初めて出てきます。

## ハッカソン1時間版のスコープ

「レシピを取り込む → 分量を変える → 始める前に準備を確認 → 手を触れずに作る」の一本道だけを作ります。

**やること**

1. レシピのURLを貼り付け、サーバー側でページを取得して、Claude APIで材料と手順に構造化する（本文の貼り付けにも対応）
2. 基準にする材料の量を変えると、全体が比率で変わる
3. 始める前チェックリスト：後半に出てくるけれど事前にやること（予熱、常温に戻す、お湯を沸かすなど）を最初に一覧で出す
4. 調理モード：大きな文字で1画面1ステップ、画面全体タップで次へ、画面を消さない（Wake Lock）

**やらないこと**：音声操作、YouTube対応、段取りの時刻逆算、オーブン補正、スケール連携、パン日記

**時間配分**

| 時間 | やること |
| --- | --- |
| 0〜10分 | ひな形（Next.js 1画面）とAPIルート |
| 10〜35分 | URL → ページ取得とテキスト化 → Claude API（構造化出力） → 材料と手順を表示 |
| 35〜45分 | 分量換算と始める前チェックリスト |
| 45〜55分 | 調理モード（画面タップ、Wake Lock） |
| 55〜60分 | デモの練習 |

**保険**

- 入力欄は1つ。httpで始まればURLとして取得し、それ以外はレシピ本文として扱う。URLの取得に失敗したら、ページの文章をコピーして貼り付ける
- 会場のネットワークからcottaのページを取得できるか、取り込みを作った直後に確認する
- APIが応答しないときのために、取り込み済みのJSONを1件、画面から読み込めるようにしておく

## データ設計と技術構成

レシピは最初から公開版を見据えた形で取り込み、1時間版ではその一部だけを使います。

**技術構成**

| 項目 | 内容 |
| --- | --- |
| フロント | Next.js（App Router）+ TypeScript、スマホのブラウザで表示 |
| サーバー | Next.jsのAPIルート。レシピページの取得とテキスト化もここで行う。APIキーはここだけに置き、`.env.local` で持つ |
| LLM | Claude API（`@anthropic-ai/sdk`）。モデルは `claude-haiku-5-5`、精度が足りなければ `claude-sonnet-5-5` |
| JSON化 | 構造化出力（`output_config.format` に `type: "json_schema"`）でスキーマに沿うことを保証 |
| ブラウザAPI | Wake Lock（画面を消さない） |
| 保存 | なし（1時間版はメモリ上のみ） |

**レシピのJSON**（太字が1時間版で使う項目）

- `title`：レシピ名
- `yield`：何人分・型の種類とサイズ（公開版で型サイズ換算に使う）
- **`ingredients[]`**：`name`、`original`（元の表記「3個分」「大さじ1」）、**`grams`**（グラム換算値）、`estimated`（換算が推定かどうか）
- **`prepTasks[]`**：始める前にやること。`text`、`timing`（「最初に」「生地作りの途中で」など）
- **`steps[]`**：**`text`**、`timerSec`（待ち時間）、`alerts[]`（焼成中の「40分でアルミホイル」のような途中の知らせ）

**分量換算の考え方**：基準にする材料を自由に選べるようにする。パンなら強力粉、チーズケーキならクリームチーズ。お菓子は粉の量が少ないことがあるため、粉固定にはしない。

**公開時の注意**：取り込み元サイトの利用規約を確認し、元レシピへのリンクを必ず表示する。手順の写真は転載しない。

## 公開版ロードマップ

ハッカソン版のデータの形の上に、次の順で機能を積んでいく想定です（順番は未確定）。

1. **取り込みの強化**：JavaScriptで中身を描画するページにも対応する。ページに構造化データ（schema.orgのRecipe）があれば優先して使う
2. **段取りの逆算**：「15時に焼き上げたい」から、バターを出す時刻や予熱開始の時刻を通知。予熱は「最初に」ではなく「ちょうどいいタイミングで」調理モードに差し込む。室温で発酵時間も調整
3. **YouTube対応**：動画をステップごとに区切り、「次」でそのステップだけをループ再生。YouTubeの規約を確認してから
4. **マイオーブン**：機種と焼き上がりの感想を記録し、温度と時間の補正をすすめる。焦げムラ対策で天板の向きを変える通知も
5. **型サイズ換算**：15cm→18cmなど、面積比で全体を換算
6. **スマートスケール連携**：Bluetoothのキッチンスケールとつなぎ、目標の重さで音で知らせる。継ぎ足し計量にも対応
7. **パン日記**：写真、室温、湿度、粉の銘柄、結果を記録し、うまくいった条件を再現できるようにする

公開版では、音声操作（「次」「戻る」）や、ネイティブアプリ化（React Native）で近接センサーによる「手をかざして次へ」も検討できます。

## プレゼン台本

持ち時間は3分想定です。デモ用のスマホは平らに置き、画面を映しながら話します。

**1. つかみ（30秒）**

> 最近パン作りにはまっています。これはcottaという製菓材料サイトのチーズケーキのレシピです。上から順番に作っていくと……ページの下の方で「150℃に予熱しておいたオーブン」と出てきます。それ、早く言ってよ！となったことがある人、いませんか。

（元のレシピページをスクロールして見せる）

**2. 課題（30秒）**

> パンやお菓子作りには、他にも困ることがあります。生地を触った手ではスマホを触れない。分量を変えると全部計算し直し。バターを常温に戻し忘れる。今日はこの3つを解きます。

**3. デモ（1分30秒）**

1. cottaのレシピURLを貼り付ける → 「材料と手順が整理されました」
2. クリームチーズを200gから300gに変える → 「全部の分量がいっせいに変わります。卵黄の「3個分」もグラムで出ます」
3. 始める前チェックリスト → 「元のレシピでは下の方にあった予熱と、湯せん用のお湯が、最初に出てきます」
4. 調理モード → 平置きのスマホを肘でタップ → 「生地まみれの手でも進められます」

**4. 仕組み（20秒）**

> レシピのページを取ってきて、その文章をClaude APIに渡して、材料・手順・「先にやっておくこと」を決まった形のJSONで返してもらっています。レシピをデータとして持つので、換算も並べ替えもできます。

**5. 今後と締め（10秒）**

> この先は、「15時に焼き上げたい」から段取りを逆算したり、自分のオーブンの癖に合わせて温度を補正したりできるようにして、公開を目指します。ありがとうございました。
